## Constraints

- CC BY-ND 4.0: redistribute upstream XLSX verbatim; deterministic CSV extraction only; no derivative content authored on top of upstream rows.
- Prod safety: Phase 3 requires Supabase point-in-time snapshot before applying. Hard-delete is gated on `check-scf-deletion-safety.ts` reporting zero customer FK references to removed IDs (otherwise abort + manual triage).
- Never `--no-verify`, never `SKIP_SPEC_CHECK=1`.
- Never commit `.env.*` or service-role keys.
- Sandbox-first: every change exercised against a sandbox Supabase project before prod.
- Phase 4 (Compensating Controls + Data Privacy Mgmt Principles tables) is explicitly deferred — extract to CSV, do not build tables/app surface in this project.

## Scope

### In scope

- **Phase 1 — Foundation:** vendor XLSX, write `data/PROVENANCE.json`, build `scripts/extract-scf.ts`, build `scripts/verify-scf-extraction.ts`, regenerate `data/README.md` + `data/LICENSE_AUDIT.json`, delete broken `scripts/scf-license-audit.ts` and its test, delete duplicate CSVs.
- **Phase 2 — Seed rewrite:** build `scripts/seed-all.ts`, build `scripts/seed-verify.ts`, snapshot `data/seed/expected_row_counts.json`, ship `supabase/migrations/<ts>_seed_scf_control_integrations.sql`, write `SEEDING.md`, retire `scripts/import-scf-data.js`.
- **Phase 3 — Prod migration:** build `scripts/diff-scf-versions.ts`, build `scripts/check-scf-deletion-safety.ts`, author `supabase/migrations/<ts>_upgrade_scf_to_2026_1_1.sql`, execute against prod with snapshot + verification.

### Out of scope

- Phase 4: tables and app surface for Compensating Controls + Data Privacy Mgmt Principles sheets.
- Replacing the in-app SCF uploader UI (`app/api/scf/import/route.ts`).
- Multi-version vendoring (only 2026.1.1 is shipped).
- Backwards-compat shims for deleted CSV filenames.
- File-naming convention overhaul beyond the canonical names in the design spec.
